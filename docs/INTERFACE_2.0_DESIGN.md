# HYPERCOLOR — Interface 2.0

Архитектурный проект Phase 2A. Дата: 16 ноября 2026 года.

Документ описывает будущую реализацию, а не уже существующие возможности. В этой фазе меняется только документация. DSP, APVTS и интерфейс остаются без изменений.

## 1. Аудит текущего интерфейса

### Подтверждённая структура

`PluginEditor` владеет `HypercolorLookAndFeel`, `GranularVisualizer`, шестью слайдерами и кнопкой Reverse. Слайдеры управляют Density, Size, Position, Pitch, Dry/Wet и Output Gain. Используются шесть `SliderAttachment` и один `ButtonAttachment`; ID компонентов совпадают с ID параметров. Attachments объявлены после контролов и уничтожаются раньше них. LookAndFeel отсоединяется в деструкторе Editor.

Position хранится в APVTS как 0–1, но отображается в процентах. Подпись объясняет направление: 0% — свежая история, 100% — старая. Pitch отображается в semitones, Reverse явно показывает On/Off. Эти семантики необходимо сохранить.

Текущие размеры: минимум 760×560, основной 1100×700, максимум 1600×1000. `resized()` размещает header, крупную визуализацию и нижний ряд Granular/Master в соотношении 70/30. Это подходит семи контролам, но не всей реализованной обработке.

LookAndFeel уже централизует тёмную палитру, cyan/pink/lime, угловатые кнопки и кастомные rotary-контролы. Header рисует wordmark и фиксированную строку версии V0.1.0. Полноценного preset browser нет: Processor предоставляет одну программу без имени. Нет Macro X/Y, FX-панелей и выходных meters.

### Телеметрия

`GranularVisualizer` — единственный потребитель очереди в текущем Editor. Его Timer работает на 30 Hz, выполняет максимум восемь чтений за callback и сохраняет последний извлечённый snapshot по значению. Конструктор отбрасывает накопившиеся данные, начиная с `WAITING FOR AUDIO`; деструктор останавливает Timer. Это поведение сохранить.

Существующие данные: до 256 waveform points, до 64 гранул, границы истории, sample rate, generation и sequence. Это не телеметрия выхода, не meter после FX и не индикация активности каждого эффекта.

Обнаруженное ограничение геометрии: waveform растягивается на всю область по числу точек, а гранулы позиционируются относительно logical boundaries. Для неполной истории эти шкалы могут не совпадать. В будущей UI-фазе waveform нужно размещать через `waveformOldest/waveformNewestExclusive` на той же временной шкале, что и гранулы, с отсечением по границам. После смены generation нельзя интерполировать геометрию между старым и новым состоянием.

После первого snapshot нет отдельного признака давности отображения. Можно добавить UI-индикатор «Нет свежих данных», но он не должен утверждать, что транспорт остановлен: отсутствие публикации не доказывает состояние хоста.

### Параметры и состояние

`PluginParameters.h` содержит стабильные ID Granular и всех восьми FX. Processor кэширует указатели на атомарные значения APVTS и формирует параметры обработки на границе host block. Общие Dry/Wet и Output Gain имеют существующее сглаживание. Новая UI-архитектура не должна менять его.

Состояние сохраняется как XML APVTS в бинарном контейнере, корень `HYPERCOLOR_STATE`, `schemaVersion = 1`. Загрузка проверяет значения, добавляет отсутствующие параметры с defaults и вызывает `replaceState`. Это основа совместимости; нельзя заменять её новой независимой системой пресетов.

EffectChain содержит восемь внешне принадлежащих Processor модулей в порядке:

`Granular → Space → Modulation → Drive → Tape → Bitcrush → Filter → Compressor → Delay → Global Dry/Wet → Output Gain`.

Состав Chain неизменяем после prepare. `EffectModule::setBypassed()` изменяет обычный bool; это не потокобезопасный UI API. В текущем списке APVTS отсутствуют параметры bypass модулей. Следовательно, работающий bypass в новом Rack требует отдельной небольшой интеграции, а не прямого вызова из кнопки.

### Что сохранить и что переработать

| Элемент | Решение |
| --- | --- |
| Палитра и LookAndFeel | Сохранить, расширить едиными размерами, типографикой и состоянием focus |
| Attachments и IDs | Сохранить; новые представления подключать к тем же параметрам |
| GranularVisualizer | Сохранить получение данных и рисунок; исправить шкалу, адаптировать компоновку |
| Editor | Превратить в координатор layout, не помещать в него логику макросов |
| Семь существующих контролов | Сохранить доступность и поведение; переместить в Granular/Master |
| Header | Переработать; версию брать из метаданных сборки, не дублировать строку |
| FX, макросы, presets, meters | Новые возможности отдельными фазами, не изображать их уже работающими |

Существующие ProcessorTests проверяют attachments после state restore, размеры 760×560, 900×620, 1100×700, 1320×840, 1600×1000, bounds и пересечения, отрисовку, mono/stereo telemetry и повторное открытие Editor. Их следует расширять, а не заменять только screenshot-тестами.

## 2. Концепция

«Digital Chaos Laboratory»: одна выразительная круговая площадка для исполнения, рядом — реальная гранулярная история, ниже — доступный для анализа тракт эффектов. Асимметрия достигается разными размерами зон, а не нарушением выравнивания текста и контролов.

Цвета остаются прежними: фон #090A0F, панели #191B25, cyan #00E5FF, pink #FF3CAC, lime #D6FF3F. Cyan обозначает X, pink — Y, lime — выбор/подтверждение. В granular-поле цвета направления сопровождаются стрелками: цвет не единственный носитель смысла.

Крупный wordmark, спокойные числовые значения, короткие технические подписи. Никаких случайных движений, фиктивных спектров, CPU-показателей или аудиореакции без измерений. XY не осциллограф и не декоративная анимация.

## 3. Главная страница

Основной размер предлагается 1200×760. Слева круговой XY; справа сверху Granular Field, ниже инспектор выбранного раздела. Под ними — FX Rack в реальном порядке обработки. Master всегда виден в нижней полосе. Macro X/Y и список назначений находятся рядом с кругом.

```text
+-----------------------------------------------------------------------+
| HYPERCOLOR       [Пресет / Изменён] [Открыть] [Сохранить]       версия   |
+----------------------------------+------------------------------------+
| ИСПОЛНЕНИЕ                       | GRANULAR FIELD                     |
|          .--------------.        | [waveform L/R + реальные гранулы]  |
|       .-'       Y        '-.     | СТАРОЕ <------------------> СВЕЖЕЕ |
|      /          |           \    | история / количество гранул        |
|     |     ------o------ X    |    +------------------------------------+
|      \                      /    | [GRANULAR] [ВЫБРАННЫЙ FX]          |
|       '-.________________.-'     | Контролы выбранного раздела        |
| X 50%     Y 50%   [Назначения]    | Значение / единицы / назначение    |
| X: Size, ...  Y: Cutoff, ...      | Расширенные параметры по раскрытию |
+----------------------------------+------------------------------------+
| FX: SPACE > MOD > DRIVE > TAPE > CRUSH > FILTER > COMP > DELAY          |
+-----------------------------------------------------------------------+
| MASTER     Dry/Wet [100%]   Output [0 dB]      [L/R meters: позже]      |
+-----------------------------------------------------------------------+
```

Это схема зон, а не обещание вместить все параметры одновременно. Rack выбирает инспектор, не открывает восемь панелей разом. Granular остаётся доступен отдельной вкладкой. Все существующие granular-вариации доступны в расширенной части инспектора без новых DSP-функций.

Preset header сначала показывает «Текущее состояние». Имя пресета и признак «Изменён» появляются только вместе с реальным сохранением/загрузкой. «Изменён» относится к сохранённому пресету плагина, а не к состоянию проекта DAW. Сравнение A/B, undo и каталог factory presets не входят в первый UI-релиз.

## 4. Спецификация кругового XY

### Геометрия и значения

Предлагаются два новых независимых APVTS Float: `macroX` и `macroY`, диапазон 0–1, default 0.5. Без назначений они не меняют звук. Круг — декартова область: X растёт вправо, Y вверх. Радиус перемещения учитывает радиус маркера, чтобы маркер не обрезался.

Для центра `(cx, cy)` и доступного радиуса `r`:

`u = (mouseX - cx) / r`, `v = (cy - mouseY) / r`.

Если `u² + v² > 1`, разделить обе координаты на `sqrt(u² + v²)`. Затем `X = (u + 1)/2`, `Y = (v + 1)/2`. Пустые/слишком малые bounds не принимают ввод; нечисловые значения не передаются параметрам.

**Неустранимый компромисс буквального круга:** жест не достигает пары X=1, Y=1 и других углов квадратного пространства двух независимых параметров. Рекомендуется сохранить линейные оси и не искажать существующую host automation. Если DAW или числовой ввод устанавливают точку вне круга, точные X/Y остаются действующими, маркер проецируется на окружность и показывается подпись «Вне круговой области». Числа всегда показывают реальные значения. UI не записывает исправленные значения обратно из repaint/Timer.

Такое состояние не полностью кодируется положением маркера — это явное ограничение, требующее подтверждения. Альтернатива — взаимно однозначное отображение квадрата в диск, позволяющее все пары, но нарушающее независимую линейность визуальных осей. Не смешивать эти два режима неявно.

### Взаимодействие

- Mouse down внутри круга, вне маркера: абсолютный переход к точке с началом жестов обоих параметров.
- Захват маркера: сохранить смещение курсора, чтобы начало drag не давало скачка.
- Drag вне круга: радиальная проекция, без отпускания захвата.
- Mouse up, отмена захвата или закрытие Editor: завершить начатые host gestures ровно один раз.
- Shift-drag: относительное точное перемещение с чувствительностью 0.1; не прыгать при смене модификатора.
- Двойной щелчок: центр 50/50 через оформленный gesture; context menu не меняет значения.
- Доступны клавиатурный focus, стрелки по 1%, Shift по 0.1% и независимый числовой ввод X/Y.

Применить два `juce::ParameterAttachment` для кастомного компонента; обычные слайдеры X/Y могут использовать SliderAttachment. Источник истины один — APVTS. UI обновления от host/state не открывают обратный gesture. Две оси не являются атомарным sample-accurate событием хоста: на первом этапе значения читаются один раз за host block.

Маркер имеет контрастный контур и увеличенную невидимую область захвата. Оси, четверти и тонкие концентрические линии помогают ориентироваться. Никакого инерционного движения после отпускания. Рядом показываются X/Y и краткие назначения; полный список открывается в инспекторе.

Загрузка пресета восстанавливает X/Y и назначения, не анимирует DSP между состояниями и не пишет automation от имени UI. Отрисовка показывает восстановленные значения. Для последующего расширения компонент не должен хранить глобальные static-параметры; вторую площадку и дополнительные IDs сейчас не вводить.

## 5. Macro Assignment System

### Минимальная модель

Processor владеет конфигурацией независимо от Editor. Максимум 16 назначений, по восемь на ось. Запись содержит ось, стабильный target ID, Min, Max и enabled. В аудиопути строковые ID заранее преобразованы в компактный enum; никаких строковых поисков, ValueTree или указателей на UI.

MVP разрешает только непрерывные параметры из явного списка поддерживаемых granular/FX целей. Choice, bool, bypass, сами макросы и Master исключены. Один target может принадлежать только одной оси; повторное назначение требует явного переноса. Это исключает неочевидное сложение двух макросов. Значения Min/Max отображаются в физических единицах, хранятся нормализованными; Min > Max разрешает обратное направление.

Для macro `m`:

`effectiveNormalized = clamp(Min + m * (Max - Min), 0, 1)`.

Преобразование в физическое значение соответствует диапазону конкретного существующего параметра, включая skew и шаг. Описание преобразований фиксируется заранее; менять существующий диапазон APVTS ради макроса нельзя. Невалидные значения и неизвестные targets отклоняются при создании конфигурации, до публикации.

### Базовые значения и automation

APVTS target хранит базовое значение. При включённом назначении оно временно перекрывается эффективным значением только в POD snapshot обработки. Макрос не вызывает `setValueNotifyingHost()` для целевых параметров, особенно из audio thread. DAW автоматизирует X/Y либо независимые базовые параметры; базовая automation назначенной цели сохраняется, но не влияет на звук до отключения назначения.

Инспектор явно показывает «Управляется X/Y», базовое и расчётное целевое значение раздельно. Обычное редактирование базовой ручки назначенного параметра блокируется в UI; редактируются Min/Max или снимается назначение. Это не блокирует automation со стороны DAW. Не подменять значение стандартного attachment эффективным значением.

При создании назначения обе границы сначала равны текущему базовому значению: само назначение не вызывает скачка звука. Пользователь затем раскрывает диапазон. Снятие назначения возвращает актуальную базу через существующее сглаживание модуля; где его недостаточно, потребуется небольшой переход именно в слое эффективных параметров. Granular-параметры по-прежнему фиксируются при запуске новых гранул. Нельзя обещать отсутствие щелчков для всех целей без тестов конкретных переходов.

### Передача конфигурации в audio thread

Рекомендуется фиксированный атомарный mailbox конфигурации, а не обычный ValueTree или seqlock с неатомарным payload. Все поля публикации — lock-free атомарные целые слова; float кодируются битовым представлением. Версия — атомарный uint64. Требуются compile-time проверки lock-free на поддерживаемой платформе.

Редакторы конфигурации (message thread и загрузка state хостом) сериализуются mutex **только вне audio callback**. Они публикуют нечётную версию, все слова фиксированного payload, затем следующую чётную версию. Для первой реализации все эти atomic операции используют `memory_order_seq_cst`: простая доказуемая последовательность важнее преждевременного ослабления ordering.

Audio thread один раз за блок читает версию; если чётная — копирует фиксированное число атомарных слов и повторно читает версию. При совпадении чётных версий принимает конфигурацию; иначе оставляет последнюю принятую. Нет retry-loop, ожидания и чтения памяти, изменяемой неатомарно. При отсутствии полного оборота 64-битного счётчика за одно чтение равенство версий означает отсутствие записи между проверками; seq_cst обеспечивает единый порядок операций. Переполнение должно быть отдельно оговорено и протестировано, а не использовать знаковую арифметику.

В отличие от заполненной очереди, последнее опубликованное состояние не теряется и будет прочитано следующим блоком даже при закрытом Editor. Стресс-тест и ThreadSanitizer обязательны перед принятием реализации. Это небольшая специализированная структура для 16 назначений, не общий modulation framework.

Порядок audio block: прочитать базовые APVTS значения и X/Y → попытаться принять конфигурацию → вычислить максимум 16 назначений → подставить значения в существующие POD snapshots → вызвать текущие DSP-модули. Никаких новых обходов аудиоистории. Автоматизация block-rate; sample-accurate обработка вне этой фазы.

UI может вычислять целевые значения из своей копии конфигурации для отображения, но обозначает их как целевые, не как уже достигнутые сглаженные DSP-значения. Для индикации принятой конфигурации достаточно отдельного атомарного номера подтверждения audio thread; не читать изменяемые структуры DSP.

### Сохранение

Добавить дочерний раздел `MACRO_ASSIGNMENTS` с собственной версией формата 1 в существующее состояние. В файле сохраняются строковые стабильные target IDs, не порядковые индексы enum. На загрузке проверяются ёмкость, повторные цели, оси, конечность и диапазон Min/Max. Неизвестная цель пропускается; неизвестная версия раздела отключает назначения с диагностикой вне audio thread. Старое состояние без раздела означает пустую конфигурацию и defaults X/Y, даже если до загрузки уже были назначения.

Для первого расширения можно сохранить корневую schemaVersion=1: новые параметры добавляются через существующую миграцию, вложенный раздел версионируется отдельно. Это требует fixture-тестов; старые бинарные версии могут проигнорировать новые данные и потерять их при повторном сохранении. Гарантия — загрузка старых состояний новой версией, не сохранение макросов старой версией.

Сериализация/парсинг и mutex модели не вызываются из `processBlock`. Host state callbacks нельзя считать message-thread callbacks. Структурная конфигурация сохраняется под её не-аудиоблокировкой, APVTS — штатным механизмом. Существующее чтение нескольких APVTS atomics не обеспечивает атомарного снимка всего пресета: кратковременная смесь значений при активной загрузке возможна. Полную транзакционную загрузку звучащего пресета не обещать в MVP; если она обязательна, выделить отдельный этап, а не скрывать эту проблему mailbox-ом назначений.

## 6. FX Rack

Восемь карточек в фактическом порядке Chain. Каждая показывает имя, выбранный режим, одно ключевое числовое значение и состояние bypass, когда оно будет реализовано. Выбор карточки открывает её существующие параметры в одном инспекторе; доступ ко всем параметрам, включая Compressor, обязателен. Количество контролов задаётся конкретной панелью, без динамического reflection framework.

Акцент карточки означает выбор или enabled, не наличие аудиосигнала. Существующая telemetry не позволяет рисовать активность Space, Delay или gain reduction Compressor. Такие meters откладываются до реальных измерений.

Для bypass добавить в будущей фазе по одному стабильному APVTS bool на модуль, default «обработка включена», без изменения старых ID. Snapshot читается audio thread; UI никогда не вызывает `setBypassed` напрямую. Текущий bypass пропускает process и тем самым приостанавливает состояние эффекта. До подключения кнопок выбрать и протестировать переход: короткий crossfade с dry, затем пропуск обработки; выход из bypass — контролируемый reset/возобновление с crossfade. Простая кнопка без этого не гарантирует отсутствие щелчков и корректный хвост.

Сохранение хвостов при bypass — отдельное решение, не уже доступная функция. Mix=0 не объявляется эквивалентом bypass: внутреннее состояние и затраты CPU могут отличаться.

Перестановка модулей пока запрещена: не рисовать работающие drag handles. В будущем карточки должны идентифицироваться стабильным module ID, а не номером позиции, но безопасное обновление порядка потребует отдельного изменения контракта Chain. Текущие восемь слотов уже заняты; добавление эффектов не относится к редизайну.

## 7. Адаптивная компоновка и HiDPI

Предлагаемые размеры: минимум сохранить 760×560; основной 1200×760; максимум расширить до 1920×1200. Координаты JUCE логические, не физические пиксели. Не умножать layout вручную на масштаб экрана. Векторная геометрия и текст рисуются заново; избегать raster assets для шкал.

При ширине от 1000: две колонки, XY около 45%, история и инспектор около 55%; круг ограничивается меньшей стороной выделенной области. При 760–999: XY слева не меньше 280×280, справа переключаемая область «История / Параметры / Назначения». История остаётся доступной, но не конкурирует со всеми ручками одновременно. Rack — две строки по четыре карточки. Master всегда внизу. Длинные панели используют вертикальный viewport, не уменьшают текст до нечитаемого размера.

Ориентиры минимального layout по высоте: header 48, рабочая область 340, Rack 64, Master 48, остальные 60 — отступы. Внутри рабочей области XY занимает 280 и оставляет 60 для значений. Это проверяемый бюджет, а не масштабирование большого макета целиком.

Основной текст 14–16 логических px, микроинформация не ниже 12, интерактивная область кнопок не меньше 28×28. Focus и selected различимы без цвета. Числовые поля поддерживают ввод с клавиатуры. Обрезается второстепенное описание с tooltip, но не значение или единица измерения.

Проверить 760×560, 900×620, 1000×700, 1200×760, 1600×1000, 1920×1200; отдельно масштабы 1× и 2×, перенос окна между экранами, длинные имена пресетов и открытый assignment inspector. Окончательные размеры подтверждаются реальным прототипом; в этой фазе визуальных проверок новой компоновки ещё нет.

| `src/plugin/PluginParameters.h` | Только новые стабильные IDs в будущих фазах |

Header и Master первоначально можно оставить небольшими группами в Editor: отдельные классы не обязательны. Не создавать базовый класс для каждой панели. Attachments живут не дольше контролов; при смене инспектора сначала уничтожаются attachments. Создание UI-контролов допустимо только message thread.

Сохраняется ровно один consumer granular queue. Другие UI-компоненты получают копию уже прочитанного состояния через message-thread вызов, а не сами читают Processor. Если позже общий telemetry controller заменит visualizer как consumer, это должна быть полная передача роли, не второй Timer с чтением той же очереди.

Preset header сохраняет тот же Processor state, а не отдельный формат параметров. Размер окна и выбранная вкладка — UI preferences; они не должны помечать звуковой preset изменённым. Дополнительные метры получают реальные bounded audio→UI данные отдельной фазой; отсутствие этих данных нельзя компенсировать анимацией.

Проверить математические диапазоны, inverse mapping, приоритет над базой, отключение, concurrent publication, restore без Editor, нулевые аллокации и сохранение granular snapshot semantics.
4. **2E — рабочий FX bypass.** Новые bool IDs, audio-thread переключение, переходы и хвосты по утверждённой политике. Проверки каждого эффекта, автоматизации, старого state и отсутствия щелчков/нефинитных значений.

Проверять отсутствие allocation/lock в audio callback и сохранение исходного аудио при пустой конфигурации. Проверки потоков проводить без второго consumer существующей telemetry queue.

## 10. Риски и решения, требующие подтверждения

Основные риски: неоднозначность круглого XY при независимой автоматизации; конфликт базовой automation с макросом; безопасная публикация назначений; переключение bypass с хвостами; рассогласование временных шкал визуализации; попытка показать meters без данных; недостаток места на минимальном размере; загрузка всего state не как единая аудиотранзакция.

До реализации подтвердить:

1. **XY:** буквальные линейные оси с круговым ограничением жеста и явной индикацией внешних значений вне диска — либо нелинейное отображение всего квадрата в круг.
2. **Макросы:** default 50/50, пустые назначения, максимум восемь целей на ось, одна ось на target, абсолютный Min/Max вместо аддитивной модуляции.
3. **Приоритет:** назначенный target временно перекрывает базовую automation; базовое значение сохраняется и возвращается после снятия назначения.
4. **Layout:** основной 1200×760, минимум 760×560, максимум 1920×1200; на малом окне история и инспектор разделяют вкладочную область.
5. **Bypass:** требуется ли сохранение хвостов или допустим crossfade с последующим reset/пропуском обработки. До решения кнопки не выдаются за готовую функцию.
6. **Presets/meters:** отдельная фаза после работающих XY/assignments; без A/B, перестановки FX и нескольких XY в первом выпуске.
7. **Загрузка состояния:** допустима существующая block-rate модель без гарантии атомарного переключения всех параметров звучащего пресета или нужна отдельная транзакционная реализация.

Рекомендуемый первый шаг — 2B: оболочка и инспектор на существующих APVTS attachments. Архитектура позволяет начать эту часть независимо от решения по круговому XY; реализацию макросов следует начинать после подтверждения пунктов 1–3.
